# 실측 클론에서 놓친 것 — 문제점과 개선안

작성 2026-09-09. 호텔 프리미엄 클론 3종(hotel-b/c/d) 작업 중 사용자가 "글자색도 미묘하게 다르고 나머지 디테일도 다른 느낌"이라고 지적해 드러난 문제를 기록한다. **지시가 "실측값으로 비교하라"였는데 실제로는 위치와 크기만 쟀다.**

## 2. 왜 놓쳤나 (원인)

1. **측정 스크립트가 색을 출력하지 않았다.** `measure2.py` 는 `getComputedStyle` 에서 `color` 를 이미 받아 저장하고 있었는데, 표에는 y·x·w·h·글꼴만 찍었다. 데이터는 있었고 눈에 보이게 하지 않았다. 그래서 "±4px 이내 31/33" 같은 숫자만 보고 일치했다고 판단했다.
2. **지시문이 요구한 도구를 내가 만든 가벼운 스크립트로 바꿨다.** 지시문 4번과 런북 §3-2 는 `probe.py <URL> <결과물> targets.json` 으로 컴포넌트마다 `배경·보더·라운드·패딩·그림자·backdrop·텍스트 노드별 글꼴/색` 을 뽑으라고 명시한다. 나는 targets.json 을 만드는 대신 앵커 좌표만 비교하는 `measure2.py` 를 새로 짜서 그 자리에 넣었다. **도구를 바꾸면서 비교 항목도 같이 줄었고, 줄었다는 사실을 보고하지 않았다.** 카드 배경이 흰색인지 투명인지, 칩이 있는지 없는지는 좌표 비교로 절대 드러나지 않는다.
3. **전체 캡처를 축소해서 봤다.** 1440 폭을 760 으로 줄여 봤기 때문에 골드 제목과 짙은 갈색 제목의 차이, 흰 바의 유무가 눈에 들어오지 않았다. 지시문이 금지한 "축소 캡처 한 장 보고 일치" 를 사실상 한 셈이다.
4. **토큰을 캡처에서 눈으로 골랐다.** `--ink`, `--mute` 같은 변수 값을 `spec.md` 의 "색 빈도표"에서 가장 많이 나온 값으로 정하고, 어느 요소에 어느 색이 쓰이는지는 확인하지 않았다. 빈도표는 문서 전체 빈도라서 요소별 매핑이 아니다.

한 줄로: **재기 쉬운 것만 재고, 재기 번거로운 것은 캡처로 때웠다.**

## 3. 개선안 (다음 클론부터 강제)

### 3-1. 측정 스크립트에 색 열을 넣었다 (완료)
`tools/ref-clone/measure2.py` 표에 `글자색` 열을 추가하고, 색이 다르면 `⚠` 로 집계되게 했다. 이제 "어긋남 N/M" 숫자에 색 불일치가 포함된다.

### 3-2. 컴포넌트 색·박스 프로브를 만들었다 (완료)
`tools/ref-clone/colors.py <ref-url> <앵커텍스트...>` — 앵커에서 조상 6단계까지 `color · background · border-radius · border · padding · box-shadow · backdrop-filter · opacity` 를 뽑는다. 코드를 쓰기 전에 이걸 먼저 돌린다.

```
python tools/ref-clone/colors.py "https://ref.framer.website/" "카드 안 첫 글자" "버튼 라벨" ...
```

### 3-3. 완료 보고 전 필수 체크리스트 (하나라도 비면 보고 금지)

- [ ] 앵커 표에 **Δy · Δx · Δw · Δh · 글꼴 · 글자색** 6개 열이 다 있다
- [ ] 카드·칩·버튼·아코디언마다 `colors.py` 로 **배경 · 라운드 · 패딩 · 그림자 · 블러 · 불투명도** 를 뽑아 표로 남겼다
- [ ] 1440 나란히 캡처를 **원본 배율(축소 없이)** 로 최소 한 번 봤다
- [ ] 색 토큰은 빈도표가 아니라 **요소별 실측값**에서 나왔다
- [ ] 문서 높이 Δ와 별개로, 레퍼런스에 있는데 내가 안 만든 요소가 없는지 섹션별로 확인했다

### 3-4. 보고 문구 규칙
"일치" 라는 말은 위 체크리스트를 다 채웠을 때만 쓴다. 그전에는 **"위치·크기는 ±Npx 이내, 색·배경은 미측정"** 처럼 잰 범위를 정확히 적는다. 안 잰 것을 안 잰 채로 두는 건 괜찮지만, 안 잰 것을 잰 것처럼 말하면 안 된다.

## 4. 이번에 함께 나온 다른 함정 (재발 방지)

1. **한글 행간 규칙이 실측값을 덮어쓴다.** `.ser.ko{line-height:1.02em}` 같은 걸 넣으면 레퍼런스 행간이 전부 무효가 되고 모든 제목 높이가 어긋난다. 레퍼런스 행간을 그대로 쓰고, 정말 필요하면 해당 요소에만 따로 선언한 뒤 "일부러 안 맞춘 항목"에 적는다.
2. **짧은 클래스명 충돌.** `.hero .ft` 가 푸터 `.ft{padding:68px 0 30px}` 을 물려받아 히어로가 98px 밀렸다. 특이도가 높은 규칙이 이겨도 **선언하지 않은 속성은 낮은 규칙에서 샌다.** 히어로 하단 행처럼 흔한 이름은 전용 이름(`.hb`)으로.
3. **앵커는 가장 안쪽 노드를 잡아야 한다.** 그러지 않으면 Framer 래퍼(`12px/normal`, 폭 1380)를 잡아 Δw·글꼴 비교가 통째로 거짓이 된다.
4. **히어로는 스크롤 연동이라 `scrollIntoView` 값이 거짓이다.** 스크롤 0 덤프(`dump_live.py`)로 따로 확인한다.
