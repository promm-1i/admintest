# 레퍼런스 사이트 클론 — 작업 절차 (런북)

"이 사이트랑 똑같이" 요청이 오면 **이 순서 그대로** 간다. 순서를 건너뛰면 travel-a 1차처럼
팔레트·타이포만 맞고 레이아웃은 딴 판이 된다.

## 스크립트 목록 (전부 `mintcl-netlify-spa/tools/ref-clone/`)

| 파일 | 하는 일 |
|---|---|
| `extract_spec.py <소스.html> <outdir>` | 저장한 소스에서 캡처·섹션 구성표·슬롯·토큰·애니메이션·플레이스홀더를 한 번에 뽑는다 |
| `capture_ref.py <url> <out.png>` | 라이브 전체 페이지 캡처 (소스 없이 URL 만 있을 때) |
| `audit.py <anchors.json>` | 레이아웃 박스(컨테이너·히어로·h2·버튼·카드 외곽·섹션 간격) 실측 |
| `probe.py <ref-url> <impl> targets.json` | 컴포넌트 안쪽 — 배경·보더·라운드·패딩·그림자·backdrop·텍스트별 글꼴/색·SVG/IMG·블롭·애니메이션 |
| `measure2.py <config.json>` | 앵커별 레퍼런스↔결과물 대조표 (`Δy·Δx·Δw·Δh·글꼴·글자색`), `sel:<CSS선택자>` 앵커 지원 |
| `colors.py <ref-url> <앵커텍스트...>` | 앵커에서 조상 6단계까지 `color·background·border-radius·border·padding·box-shadow·backdrop-filter·opacity` |
| `secdump.py <slug> <ylo> <yhi>` | 라이브 덤프에서 y 구간의 요소를 좌표·글꼴·배경까지 한 줄씩 출력 |
| `cap_any.py <url> <out.png> <폭>` | 결과물 전체 페이지를 뷰포트 단위로 이어붙여 캡처 (고정/스티키 반복 제거) |
| `overflow.py <slug> <폭>` | 그 폭에서 가로로 넘치는 요소를 찾아낸다 (가로 스크롤 원인) |

          ["같은 글자가 여러 곳이면","레퍼런스 텍스트","sel:.section h2.t"]]}

## 0. 경계 (한 줄)

레이아웃 구성 · 치수 · 리듬은 맞춘다. **코드 · CSS 텍스트 · 이미지 파일 · 문구를 그대로 복사하지 않는다** (제3자 유료 템플릿).
사용자가 긁어온 소스(DOM 덤프)와 라이브 페이지는 **값을 뽑는 용도**로 쓴다.

**"복사 금지"를 "값도 보지 말자"로 넓히지 않는다.** (clipcut → video-a 에서 이렇게 잘못 해석해 레이아웃 박스만 맞추고
카드 안쪽을 창작했다. 사용자가 본 결과: "디테일이 하나도 안 맞는다".) 아래는 **라이브 computed style 에서 그대로 읽어 그대로 박는 값**이다:
색(배경·글자·보더) · border-radius · padding · 글꼴 크기/굵기/행간/자간 · 라틴·숫자 글꼴 패밀리(Google Fonts 에 있으면 같은 폰트를 쓴다.
한글만 한글 폰트) · 블롭의 크기·blur·opacity·위치 · SVG/IMG 의 표시 크기 · 애니메이션 길이/이징/지연/반복.
다시 만드는 것은 **마크업·CSS 문장·이미지 파일·문구**뿐이다. 이미지(3D 아이콘·앱 아이콘·글로우 PNG)는 같은 크기·같은 느낌으로 생성해 넣고
프롬프트를 `템플릿_이미지프롬프트_<slug>.md` 에 남긴다.

## 입력 — 사용자가 소스를 주는 경우 (기본 경로)

사용자는 레퍼런스 소스를 **파일로 저장하고 경로만** 준다 (채팅 붙여넣기는 2MB 넘어서 컨텍스트가 터진다).
세 형태 모두 받는다: DevTools Copy outerHTML · 크롬 "페이지 소스 보기" 화면 저장본(가장 흔함, 줄번호 테이블 안에 이스케이프됨) · 통째로 이스케이프된 텍스트.
`extract_spec.py` 가 자동으로 판별해 복원한다.

```bash
python /c/web-project/mintcl-netlify-spa/tools/ref-clone/extract_spec.py <소스.html> /c/_tmp/claude/spec-<slug>
```

나오는 것: `ref-1440.png`(전체 캡처) · `spec.md`(섹션 구성표 + 슬롯 표 + 토큰 + 애니메이션) · `slots.json` · `tokens.json` ·
`prompts.md`(슬롯별 프롬프트 뼈대) · `placeholders/`(슬롯 크기 그대로의 임시 이미지).
**소스가 있으면 1~3단계는 이 한 줄로 끝난다.** 그래도 캡처는 눈으로 4등분해서 본다 — 열 수·카드 수는 자동 추출이 힌트일 뿐이다.

렌더는 스크립트를 뺀 정적 HTML 로 한다. 이미지는 원본 CDN 에서 불러와 **크기를 재는 데만** 쓰고 결과물에 넣지 않는다.
Framer 덤프는 CSS 가 인라인이라 그대로 렌더된다. Webflow/Wix 는 외부 CSS 링크가 절대경로면 온라인 상태에서 렌더된다.

### 소스 렌더의 한계 — 라이브 캡처로 한 번 더 본다 (beauty-f 에서 배운 것)

- 정적 렌더는 **호버·스크롤 애니메이션의 초기 상태**를 찍는다. salonix 는 솔루션 카드가 사진(뒷면)으로, 후기가 부채꼴 덱(퍼지기 전)으로
  찍혔는데 라이브는 크림 앞면 + 흩어진 폴라로이드였다. `saved from url=` 이 있으면 `capture_ref.py <url>` 로 라이브도 찍어 나란히 본다.
- lazy 이미지는 스크롤 전엔 안 불러온다 → 추출기가 eager 로 바꾸고 끝까지 스크롤한다 (넣어 뒀음). 그래도 빈칸이면 라이브 캡처를 본다.
- 스크립트로만 붙는 상태(`.on` 등)는 **`html.js` 게이트**로 CSS 를 쓴다. 기본형은 스크립트가 없어서, 게이트 없이 쓰면 요소가 영영 숨는다.
- 배경 영상 슬롯이 있으면 검증 전에 **포스터로 만든 짧은 mp4** 라도 넣는다 (없으면 file:// 에서 미디어 에러 → 콘솔 에러 1).
  `ffmpeg -loop 1 -i 포스터.jpg -t 4 -vf scale=1104:690,format=yuv420p -r 12 -c:v libx264 -crf 32 out.mp4`
- 회전·절대배치 카드가 있는 섹션은 모바일에서 `nth-child` 고정폭이 살아남아 가로 스크롤을 만든다. 미디어쿼리에서 `width:auto!important`.
- **미디어쿼리는 반드시 기본 규칙 뒤에** 쓴다. 앞에 쓰면 같은 특이도의 기본 규칙에 조용히 덮인다 (beauty-f 에서 `.sol` 높이가 안 먹어 모바일 카드가 528px 로 쌓였다). 숫자 검증(가로 스크롤 0)은 통과해도 **모바일 캡처를 눈으로** 봐야 잡힌다.
- 모바일 스팟 확인은 `scrollIntoView()+screenshot` 이 아니라 `element.screenshot()` 으로. `scroll-behavior:smooth` 때문에 스크롤 전에 찍힌다.
- 세로 배치 대조는 `audit.py` 의 라벨 y 열로 섹션 시작점을 비교하고, 헤더 리듬(라벨→h2 / h2→설명 / 설명→콘텐츠)은 앵커가 잡히는 섹션 2~3개에서 재서 전역 규칙으로 옮긴다. 레퍼런스도 섹션마다 여백이 조금씩 달라 ±100px 은 남는다.

### beauty-g(afrobarbershop) 에서 배운 것

- **라이브 캡처가 깨질 수 있다**: Frameship "BUY LICENSE" 오버레이 + 모바일 브레이크포인트로 렌더돼 참고 불가였다. 그럴 땐 정적 렌더(`ref-1440.png`)를 1차 기준으로 쓰고, 정적 렌더의 빈칸(iframe 위젯 · Vimeo 영상 · 지도)은 소스에서 `<iframe>` `<video>` 를 grep 해 정체를 적는다.
- **자동 섹션 분할이 1개로 뭉치면**(모든 섹션이 한 컨테이너) 캡처를 1440 폭 그대로 9~10구간으로 잘라 눈으로 보고 `구성표.md` 를 직접 쓴다. 슬롯 표의 x/y 좌표(`slots.json`)로 어느 섹션 사진인지 붙인다.
- **Framer appear 의 y:150 초기 상태**가 스크립트 없는 덤프에 남아 h2 y 가 +150 으로 잰다. `anchors.json` 의 ref 에 `"resetAppear": true` 를 주면 audit 이 리셋한다(넣어 뒀음). 그래도 일부 요소는 래퍼에 transform 이 있어 안 풀리니, 캡처 픽셀과 측정값이 ~150 어긋나면 이 원인부터 의심한다.
- **`data-framer-name` 에 `Ticker` 가 있으면 마퀴**다. 고스트 텍스트 티커(1200×200, 200px 글자, 아이콘 108)는 레퍼런스에 실제로 있는 요소이니 만든다. 티커가 이전 콘텐츠와 겹치는 곳(초상 발끝 -48px)도 캡처대로 옮긴다.
- **Bebas Neue 같은 컨덴스드 디스플레이는 한글에 없다** → Black Han Sans 로 대체하고 자간을 -.06em → -.03em 으로 완화한다(보고에 명시). 숫자·가격은 `.en` 으로 Bebas 를 그대로 쓴다.
- **모바일에서 absolute → relative 로 바꿀 때 top/right 를 반드시 auto 로 해제**한다. 안 하면 데스크톱 오프셋이 그대로 먹어 엉뚱한 섹션 위에 뜬다(히어로 글래스 카드가 시술 카드 위에 떴다). flex `order` 로 세로 흐름을 다시 정한다.
- **appear 스크립트는 "로드 시" 애니메이션만 담는다. 스크롤 등장·스크롤 연동 효과는 라이브를 실제 Chrome(`channel='chrome'`)으로 열어 재야 나온다.** 방법: 대상 요소를 잡고 ① 위에서 스크롤해 상단이 뷰포트 820px 에 오게 한 뒤 100ms 간격으로 transform/opacity 를 2.5초 샘플링(등장 효과: y140·x150·y30·y90·y60 + 페이드, 트리거 ~하단 160px) ② 상단 위치 950→-300 을 100px 씩 옮기며 1.3s 뒤 transform 을 읽기(스크롤 연동: 갤러리·바버 scale 1.2→1 이 각각 650px·450px 구간에서 선형) ③ 스크롤 고정 상태에서 x 를 1.25s 동안 읽어 마퀴가 시간 기반인지(고스트 77px/s·인스타 108px/s·밴드 22px/s), 안 움직이는지(바버 행) 구분 ④ 새 탭으로 로드해 0.3s 간격으로 히어로 요소 opacity/transform 을 읽어 로드 시퀀스(CTA 1s·카드 1.5s 튕김·칩 1.8s)를 잡는다. beauty-g 1차는 이걸 안 해서 티커 등장·카드 슬라이드·스크롤 스케일이 전부 빠졌고 바버 행을 마퀴로 잘못 만들었다. 사용자가 "사진이 크다가 작아지며 올라온다"고 지적한 뒤에야 쟀다.
- **정적 렌더는 레이아웃도 틀릴 수 있다.** Framer 런타임이 거는 transform(히어로 사진 `translateX(-390)`)·스크롤 스케일 초기값(1.2 배 상태의 바버 420×540 → 실제 350×450)·호버 전용 요소(바버 흰 카드, 갤러리 인셋은 평소 opacity 0)가 정적 렌더에 그대로 찍혀 나온다. 그래서 **치수는 반드시 라이브를 실제 Chrome 으로 열고, 그 섹션을 화면에 넣은 상태(등장 애니메이션이 끝난 뒤)에서 잰다.** `scratchpad/compare2.py` 방식: 섹션마다 h2 로 스크롤 → 위아래로 한 번 지나가 애니메이션을 끝내고 → 1.8s 뒤 측정. 측정값과 스크린샷이 어긋나면 스크린샷(픽셀)이 맞다 — 리본이 대각선(-12°)인 것, 헤더가 비고정인 것, 영상 벽이 설명 바로 아래 980px 로 잘린 것은 전부 스크린샷으로만 잡혔다.
- **섹션 간격은 섹션마다 다르다.** 티커→h2 가 64/64/80/80/100/100/164/100 처럼 제각각이니 "전역 70" 같은 값을 쓰지 말고 섹션별로 실측해 박는다. 히어로 안 요소는 `.wrap` 기준 top 이므로 페이지 y 에서 헤더 높이(85)를 뺀다 — 이걸 안 빼서 문단·CTA·카드가 전부 85px 아래로 갔었다.
- 사용자가 "좌우폭·위아래가 미세하게 안 맞는다"고 하면 그 말이 맞다. 정적 렌더 기준 ±4px 을 "100% 일치"라고 보고하지 않는다. 라이브 재측정 표를 만들고 나서야 일치를 말한다.
- bash 에서 Windows 경로의 `\` 는 먹힌다 → 스크립트 인자는 `C:/...` 슬래시로. 안 그러면 `C:_tmpclaude...` 폴더가 프로젝트 루트에 생긴다.

## 1. 전체 캡처 먼저 — 이거 없이 디자인 시작 금지 (소스 없이 URL 만 있을 때)

```bash
python /c/web-project/mintcl-netlify-spa/tools/ref-clone/capture_ref.py <url> /c/_tmp/claude/ref.png
```

- 브라우저 페인(`mcp__Claude_Browser__*`)으로 찍지 않는다. 스크롤 캡처가 깨져서 히어로만 찍히고, 그 상태로
  진행하면 나머지를 상상으로 짜게 된다. (travel-a 1차의 실패 원인)
- 캡처가 어떤 이유로든 안 되면 **작업을 멈추고** 사용자에게 말한다. 텍스트 덤프만으로 진행하지 않는다.
- 히어로 한 장만 보고 "감 잡았다"고 판단하지 않는다.

## 2. 구성표 먼저 쓴다 — 코드보다 먼저

캡처를 4등분해서 보고, 섹션마다 아래를 표로 적는다. 이 표가 곧 구현 스펙이다.

| 섹션 | 열 구성 | 카드 수·배치 | 사진 위치 | 특이점 |
|---|---|---|---|---|
| 소개 | 3열 (텍스트 / 세로사진 / 스탯+카드) | — | 가운데 세로 | 좌하단 평점, 우하단 스토리카드 |

- **레퍼런스에 없는 요소를 만들어 넣지 않는다.** (마퀴를 발명해 넣고 "레퍼런스 리듬"이라고 방어한 사례)
- 애매하면 캡처를 다시 본다. 텍스트 덤프의 문구 순서를 레이아웃으로 추측하지 않는다.

## 3. 실측값 뽑기

앵커 JSON 을 만들고(`anchors.travel-a.json` 참고) 돌린다:

```bash
python /c/web-project/mintcl-netlify-spa/tools/ref-clone/audit.py /c/web-project/mintcl-netlify-spa/tools/ref-clone/anchors.<slug>.json
```

구현 전이라면 `mine` 쪽은 빈 페이지여도 된다 — 레퍼런스 열만 읽는다. 뽑는 것:
컨테이너 폭(라벨 x 좌표 = 콘텐츠 좌측선), 헤더 높이, 히어로 크기·여백·라운드, 라벨/h2 크기·행간·간격,
버튼·칩 높이, 카드 크기·라운드·제목 크기, 갤러리 이미지 4장 크기.

주의:
- **Framer 는 12px 래퍼 안에 span** 을 둔다. 12 로 나오면 래퍼다. 스크립트는 가장 깊은 요소를 잡지만 결과가 이상하면 의심.
- h1 좌표·워드마크 크기는 숨은 SEO 요소·SVG 에 걸린다. 신뢰하지 않는다.
- 소스 덤프가 있으면 `grep -o` 로 `font-size` · `border-radius` · `max-width` · `gap` · `padding` 분포와
  `--token-*` 색상을 뽑아 교차 확인한다. (Trova: 4px 그리드, 자간 -.03em/0 두 값, 컨테이너 1330, 라운드 8)

## 3-1. 애니메이션은 spec.md §4 값을 그대로 옮긴다

`extract_spec.py` 가 Framer 의 `<script type="framer/appear">` 정의를 읽어 **초기→최종 · 길이 · 이징 · 지연**을 뽑는다.
우리 `.rv` 는 기본이 translateY+blur 인데, 레퍼런스가 페이드만이면 **페이드만** 쓴다 (Trova: opacity 0→1 · 1~1.5s · 지연 0.8~1.2s,
히어로 사진 scale 1.05→1 · 1.5s · cubic-bezier(.12,.23,.5,1)). 레퍼런스에 없는 이동·블러·마퀴를 넣지 않는다.
`spring` 은 CSS 로 못 옮기니 비슷한 out-easing(`cubic-bezier(.12,.23,.5,1)`)으로 대체하고 보고에 적는다.

## 3-2. 카드 안쪽까지 실측한다 — `probe.py` (clipcut/video-a 실패에서 추가)

`audit.py` 는 레이아웃 박스(컨테이너·히어로·h2·버튼·카드 외곽)만 잰다. 여기서 멈추면 **치수는 맞는데 디자인이 다른** 결과가 난다.
video-a 는 "실측값 이식 완료"라고 보고한 뒤에도 120K 카드가 이랬다:

| 항목 | 레퍼런스 | 결과물 |
|---|---|---|
| 숫자 글꼴 | Bricolage Grotesque 40/40 600 | Pretendard 32/44.8 500 |
| 카드 배경 | rgb(9,4,1) 단색 · 라운드 10 · 패딩 15 | 갈색 그라데이션 · 라운드 8 · 패딩 0 |
| 차트 | 선 SVG 328×84 + 주황 막대 1개(138×24) | 막대 6개 + 선 SVG 302×108 |
| 글로우 블롭 | 2겹 (blur 74 / .46, blur 49 / .28) | 없음 |
| 애니메이션 | Framer 런타임 등장 | 선 그리기 1.6s 1회 |

그래서 **컴포넌트마다** 아래를 뽑아 표로 만들고 값을 그대로 옮긴다:

```bash
python /c/web-project/mintcl-netlify-spa/tools/ref-clone/probe.py <레퍼런스 URL> <결과물 index.html> targets.<slug>.json
# targets: [["120K 카드","120K","12만",3], ["플랫폼 카드","YoutubeShots","유튜브 쇼츠",1], ...]  (라벨, 레퍼런스 텍스트, 결과물 텍스트, 컨테이너까지 올라갈 단계)
```

뽑히는 것: 컨테이너(배경·보더·라운드·패딩·그림자·backdrop) · 텍스트 노드별 글꼴/색 · SVG·IMG 표시 크기와 src · 블롭(absolute 요소의 크기·blur·opacity·위치) ·
animation/transition 정의 · **등장 모션 샘플**(요소를 뷰포트 아래서 끌어올린 뒤 2.4s 동안 opacity/transform/filter 변화).

규칙:
- 카드 하나당 표 하나. "카드 시스템 공통값" 한 줄로 퉁치지 않는다 — 레퍼런스도 카드마다 다르다(가격 카드 rgba(0,0,0,.4) · 문제 카드 투명+블롭 2겹 · 후기 셀 white 5%).
- 글꼴 패밀리는 라틴·숫자 부분을 레퍼런스 것으로 그대로 쓴다(Google Fonts 링크). 한글만 한글 폰트. 이걸 안 하면 전 섹션이 "다 다르게" 보인다.
- 차트·링·게이지 같은 SVG 는 레퍼런스 SVG 의 표시 크기와 구성(선 1개인지 막대 6개인지)을 보고 같은 구성으로 그린다. 값·색은 실측.
- 이미지 요소(3D 아이콘·앱 아이콘)는 CSS 도형으로 흉내내지 않는다. 같은 크기 슬롯 + 플레이스홀더 + 프롬프트.
- 헤더 고정 여부, 라벨 칩 유무 같은 "있다/없다"도 표에 적는다. 레퍼런스에 없는 칩(`무엇을 하나요`)을 넣지 않는다.

## 4. 구현 → 같은 스크립트로 재측정

- 구현 후 `audit.py` 를 다시 돌려 표로 대조. **±4px 안**이면 일치로 본다.
- 문서 전체 높이가 2% 안이면 세로 리듬은 맞은 것. 개별 섹션 높이는 측정 조상 차이로 흔들리니 그것만 보고 고치지 않는다.
- 한글이라서 **일부러 안 맞추는 것 두 가지**: 본문 행간(라틴 1.3~1.4 → 한글 1.7), 내비 접는 폭(한글 항목이 태블릿에서 눌리면 1023px).
  이 둘은 보고에 명시한다.

영상 슬롯이 있으면 실제 Chrome 으로 재생 확인 (`p.chromium.launch(channel='chrome')`). Playwright 기본 Chromium 은 H.264 가 없다.

## 6. 보고 형식

수치로 쓴다. "비슷하게 맞췄다"는 보고가 아니다. 측정에서 걸러낸 노이즈와 일부러 안 맞춘 항목을 따로 적는다.

(`capture_ref.py` 결과와 결과물 full-page 캡처를 2900px 구간으로 잘라 좌우 배치). 전체를 한 장으로 줄인 축소 캡처만 보고 "일치"라고 하면
video-a 처럼 글로우 모양·아이콘·글꼴 차이가 전부 묻힌다. 섹션 표(3-2)와 나란히 캡처 둘 다 없으면 완료 보고를 하지 않는다.

## 사진·영상

- 저장소에 야외 풍경 사진은 없다. 아웃도어 업종은 무조건 새로 뽑는다. 슬롯별 파일명·비율을 문서로 먼저 준다.
- 받은 원본은 표시 크기의 2배(레티나)로 줄인다. 1800×2400 급 14장이면 폴더가 13MB 가 된다.
- Gemini 영상 워터마크는 우하단 x≈1130~1185(1280×720 기준) — `crop=1104:720:0:0` 으로 자른다. 루프는 정방향+역방향 팰린드롬.
- 썸네일 캡처 전에 `video.bg` 를 제거한다 (재생 타이밍에 따라 결과가 흔들린다).
- 사진이 많은 템플릿은 폰용 축소본(`*-m.webp`, 표시 폭 2배) + `srcset` + 첫 화면 밖 `loading="lazy"` 로 줄인다(estate-a: 첫 로딩 2.4MB→~0.9MB). 단 **티커·마퀴 안의 사진과 `mask-image` 컨테이너 안의 사진에는 lazy 를 걸지 않는다** — 헤드리스에서 안 불러와지고 `verify_template.sh` 가 깨진 이미지로 센다. verify 는 srcset/poster 경로 치환과 끝까지 스크롤(1.8s 대기)을 넣어 두었다.
- Framer `spring(stiffness, damping)` 은 과감쇠(ζ>1)면 튕김이 없으니 해석해(두 지수 항)를 1s 로 샘플링해 CSS `linear()` 이징으로 그대로 옮길 수 있다(`@supports (animation-timing-function:linear(0,1))`, 폴백 베지어). estate-a 히어로 등장에 적용.

## 클래스·검증 함정 (fitness-a · dental-a · hotel-a 에서 나온 것)

- `verify_template.sh` 는 모든 `.rv` 에 `on` 을 붙인다. **다른 상태에 `.on` 을 쓰지 않는다**(FAQ·옵션 열림은 `.open`). 겹치면 검증 시 전부 열린 상태로 재고 높이가 틀어진다.
- `html.js` 게이트가 있으니 요소 클래스로 `js` 를 쓰지 않는다(dental-a 진행 단계 `.js` → 본문 폭이 280px 이 됐다). 짧은 클래스는 파일 안에서 `grep -n "\.xx[{ ,.]"` 로 충돌부터 확인한다(hotel-a `.rt` 가 내비 오른쪽과 객실 제목에 동시에 쓰여 내비가 절대배치됐다).
- 화면 밖에서 시작하는 슬라이드 등장(translateX ±500)은 IntersectionObserver 가 영원히 안 잡는다. 부모 섹션을 관찰해서 켠다.
- 기본형은 `src`/`srcset`/`poster` 만 경로 치환한다. CSS `url(./assets/…)` 은 안 바뀌어 기본형에서 ERR_FILE_NOT_FOUND 가 난다 → 배경 사진은 `<img>` 로 넣는다.
- `loading="lazy"` 는 display:none·mask·티커 안, 그리고 문서 맨 아래(끝까지 스크롤해도 1.8s 안에 못 받는) 사진에 걸지 않는다.
- 라이브 전체 캡처는 Framer 가 full_page 에서 레이아웃을 바꾸므로(요금표 세로 쌓임·햄버거) **뷰포트 단위로 스크롤하며 이어 붙인다**(`cap_stitch.py`, 고정 내비·배지는 프레임마다 숨김).
- 모바일은 데스크톱과 구조가 다른 경우가 많다(dental-a: 서비스 5번째 카드가 폰에서만 노출, 후기 슬라이더가 세로 나열, Why 사진이 열린 항목 안으로; hotel-a: 소개 첫 사진이 남색 덮개 + 흰 글자). 390 덤프에서 이미지 크기·순서를 먼저 표로 뽑고 맞춘다.

## 짧은 클래스명 충돌 — 매번 나온다 (interior-f 에서 두 번)

한 파일 안에서 `.col`(콜라주 컨테이너 vs 푸터 주소 열), `.foot`(히어로 하단 행 vs 페이지 푸터)이 겹쳐
콜라주 높이 1872px 이 푸터 주소 열에 먹고, 푸터 배경(불투명 900px)이 히어로 초대형 글자를 통째로 덮었다.
- 두 번째 규칙이 이긴 게 아니라 **선언하지 않은 속성이 흘러든다**: `.hero .foot` 이 specificity 로 이겨도
  `background` `padding` `min-height` 처럼 거기서 선언하지 않은 것은 `.foot` 값이 그대로 적용된다.
- 새 블록에 클래스를 붙이기 전에 `grep -n "\.<이름>[{ ,.]" index.html` 로 이미 쓰는지 본다.
- 컨테이너급 이름(`.col` `.foot` `.top` `.in` `.row` `.bot`)은 반드시 접두사를 붙인다(`.cg` `.ft` `.fcol`).

## 절대배치만 있는 섹션은 높이가 0 이 된다
스크롤 연출용으로 사진을 `position:absolute` 로만 배치하면 부모 높이가 잡히지 않아 문서가 통째로 짧아진다
(interior-f 상담 섹션 -3400px). 레퍼런스 섹션 높이를 `min-height` 로 직접 준다.

`측정 = 좌표` 로 좁히면 "치수는 맞는데 디자인이 다른" 결과가 나온다. 2026-09-09 호텔 클론 3종에서
위치는 ±4px 안에 들었는데 글자색이 hotel-b 30/34, hotel-c 10/27, hotel-d 18/33 틀렸다.

앵커마다 **6개**를 다 비교한다: `Δy · Δx · Δw · Δh · 글꼴(fs/lh/weight) · 글자색`.
컴포넌트마다 **7개**를 더 뽑는다: `background · border-radius · border · padding · box-shadow · backdrop-filter · opacity`.

- 앵커 비교: `python tools/ref-clone/measure2.py <config.json>` (글자색 열 포함, `sel:<CSS선택자>` 앵커 지원)
- 컴포넌트 색·박스: `python tools/ref-clone/colors.py <ref-url> <앵커텍스트...>` — 조상 6단계까지 위 7개를 찍는다

색 토큰은 `spec.md` 의 "색 빈도표"에서 고르지 않는다. 빈도표는 문서 전체 통계라 요소별 매핑이 아니다.
반드시 **해당 요소에서 읽은 값**을 쓴다.
